Yazi cheat sheet

Stock yazi keys, plus the gitp4v plugin: browse GitHub repos and Perforce depots like p4v, edit them, and pin files.

Green section headings are the plugin additions. Outside the depot view every overloaded key (o O Enter l h a d r) does exactly what stock yazi does, and e does nothing.

gitp4v: the depot view

git GitHub (your org) via gh p4 Perforce via p4 both same key, vendor wording differs yellow triangle = not committed / default changelist green triangle = committed / CL pending

Enter and move around

gv"Go to network locations": the depot view. // lists GitHub orgs and Perforce depots (different icons)
l / RightOn a git repo: load its tree and enter. On a p4 folder: list that folder (one level, lazily). On a file: open its history
h / LeftBack (from a history list: back to the file, hovered)
o / EnterOn a file: read the current version (read-only). On a folder/repo: same as l
e qLeave the depot view (back to where you were)
e lRefresh the repo / folder (local changes are re-applied)

Header shows //org/repo/dir or //depot/dir. Search, filter, find, marks and sorting all work as usual on the listed level.

Right pane

hover a folderIts contents (git: the tree; Perforce: listed on demand)
hover a fileIts history: commit / CL#, date, author/user, description
hover a history entryCommit or CL message and that file's patch (colored)
J / KScroll the preview (stock yazi)
hover an unloaded git repo"Not loaded yet. Press l or Enter to load this repo."

gitp4v: file history, view and diff

History list (press l on a file)

colorsIndex, id, date and author/user are colored like the preview
orderNewest at the top. The index is larger for newer revisions (git: commit order; p4: #rev). Your sort is forced to natural-descending and restored on h
o / EnterView the hovered version, read-only
SpaceMark versions
1 marked + oView that version
2 marked + oDiff them, newer on the left, files named name#index
3+ markedError popup: "Diff 2 versions at a time"
OEdit the underlying file (see Editing)
h / LeftBack to the file; marks are cleared

Diff program: diff in your gitp4v_opts (for example nvim -d). Unset = git diff in less.

gitp4v: pinned files

Pin anything, find it again

EPin / unpin the hovered (or marked) files. Works on local, git and Perforce files, and from a history list. In the pinned list: unpin the hovered one
gpGo to the pinned list
in the listHeader shows the path that was on screen when you pinned it. Right pane is a normal preview
o / EnterLocal pin: opens normally (symlink). git/p4 pin: current version, view-only
hReturn to where you were

Stored in ~/.local/state/yazi/gitp4v/pins.tsv (created on first pin).

gitp4v: editing

Change files both

OEdit the hovered (or all marked) files with the first opener yazi.toml's [open] rules pick (else $EDITOR). git: clone + branch. p4: sync + p4 edit
aAdd a file to the current folder (name popup, then opens it)
dDelete hovered / marked files or folders (confirm popup)
rRename the hovered file (name popup). p4: files only

The first change asks for setup: a branch name (git, default $USER<yyyymmdd>, clones to <clones>/<repo>-<branch> with a "Cloning into ..." popup) or a workspace root (p4, a depot folder containing the file; default = its folder).

git: one branch, one commit, one PR

after committingError popup on any further change until the PR is opened; then until it is merged or closed
PR merged / closedNext change starts a new branch (new name popup); the old clone is deleted
clone speedBlobless + sparse clone: a second or two; only the files you edit are fetched

Perforce: one pending CL

files openedGo to the default changelist
CL pendingError popup on any further change until it is submitted or reverted
checkout refusedError popup with p4's reason (permissions, exclusive lock, not mapped)
workspace lifetimeA client exists only while it has work: revert-all (e x) or a successful submit deletes it

gitp4v: e menu inside a GitHub repo

Press e, then

cCommit all changes (message popup)
pPull request: error popup if nothing committed; asks for title and description; rebases onto the default branch if it moved (conflict: popup says fix it in the clone); pushes; gh pr create; URL copied
sChanged-files popup (see below) or "Working tree clean"
xDiscard the local branch, its changes and its clone (confirm). A pushed copy is left alone
l / qRefresh / leave

Changed-files popup

headeryellow triangle branch (not committed) or green triangle branch (committed)
markersA added, M modified, D deleted, R renamed
j/k or Up/DownMove the selection (the list scrolls)
EnterView the diff for that file
dDiscard your change to that file (not committed only; confirm popup)
EscClose

gitp4v: e menu inside a Perforce depot

Press e, then

cCreate changelist from the default changelist (description popup)
pSubmit the pending CL (confirm popup; out-of-date files are reported with the workspace path)
vShelve the pending CL
sOpened-files popup, or "No opened files"
xRevert everything, delete the pending CL and the workspace (client + local folder) (confirm)
wMake the current folder a workspace root (creates a small client)
DDelete this workspace: the client and its local folder (confirm)
l / qRefresh / leave

Opened-files popup

headeryellow "default changelist" or green "CL 123456 (pending, not submitted)" plus [shelved]
markersA add, M edit, D delete, R move
Enterp4 diff of that file
dRevert that file (default changelist only; confirm popup)
EscClose

gitp4v: popups and errors

What you will see

toasts (corner)Loading ... (first entry of a repo/depot only), Cloning into ..., Pinned/Unpinned, results
changed-files popupyazi's own popup (the Tab one): j/k or arrows move, Enter diff, d discard / revert (confirm), Esc closes
text popupsBranch name, new file, rename, commit message, PR title/description, CL description, workspace root. Enter accepts, Esc cancels
confirm popupsDelete, discard/revert, submit, uncommitted-changes warning
Authentication boxPerforce or GitHub login problem; offers to run p4 login / gh auth login
permission boxAccess denied, checkout not allowed
